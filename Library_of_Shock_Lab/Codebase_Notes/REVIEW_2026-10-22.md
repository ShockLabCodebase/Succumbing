## 2. Numerical correctness (verified)

**`spod.m`: correct.**
- Synthetic data: sum(L)·df equals the total variance to 4 digits.
- Twin jet: symmetric + antisymmetric SPOD energy adds back to the full SPOD energy to within 1.9%. The excess is the centre row, which both halves count.

**`invspod`: reconstructed amplitude too small by a constant.**
- `spod.m` normalises the window to unit power and multiplies each FFT by sqrt(dt). `invspod` still undoes the old `1/mean(w)` scaling.
- The error factor is sqrt(dt)·Σw/‖w‖. That is about 1/28 at nfft 256 and about 1/14 at nfft 1024, both at 150 kHz.
- The shape is exact. Instantaneous frequency is unaffected. But reconstructions are not in data units, and their amplitudes change with nfft and fps, so amplitudes from different settings can't be compared.
- **Patch:** optional `dt` argument; the reconstruction script passes `1/fps`.
- **Check:** on synthetic data, the all-mode reconstruction matches the data to 5e-7. On the twin jet, the 2-mode reconstruction at St 0.43 ± 0.024 has 0.895× the RMS of the raw data FFT-band-passed over the same bins (correlation 0.905).

**`tcoeffs`: amplitude correct, phase conjugated, memory heavy.**
- `|a|` is in physical units. But `diag(...')` conjugates the coefficient, so the phase runs as e^{−iωt}.
- On these 94k-pixel records the original ran out of memory. It makes several full copies of the data, and its process pool sends each of 8 workers its own copy of the projections.
- **Patch:**
  - project only onto the requested `St_ind` frequencies;
  - remove the mean per row block (no full copies);
  - replace the per-time-step nDFT-point FFT (which kept one bin) with one sliding-DFT convolution per frequency and mode, so no parallel pool is needed.
- **Check:** identical to conj(original) to 2e-7, on synthetic data and on the twin jet (4,000 frames). The full 10k-frame twin-jet run takes 5.6 s.

**`hilbert_POD_func`: conjugated analytic signal, branches disagree.**
- `hilbert(X')'` conjugates the analytic signal, because `'` is the conjugate transpose.
- Direct branch (n_pix < n_t): the instantaneous frequency comes out negative.
- Snapshot branch (n_pix ≥ n_t, i.e. all real schlieren data): the coefficients rotate the right way, but the **modes are conjugated**. A mode animated as real(φ·e^{iωt}) then appears to travel upstream.
- The svds branch has the same conjugation.
- **Patch:**
  - correct analytic signal, computed in pixel blocks;
  - `conj(v)` in the snapshot and svds branches;
  - no duplicate `Uall` copy, which keeps the peak to about one complex copy of the data.
- **Check:** both branches give +f₀ and the same mode (|⟨φ₁, φ₂⟩| = 1). Real data gives +21.34 kHz (SPOD peak 21.39 kHz) and +9.32 kHz (9.38 kHz).

**POD `Energy` %: too high.**
- It is normalised by the 500 retained eigenvalues, not the total variance. Twin jet: mode 1 is reported as 6.65% but is really 4.41% (×1.51).
- The same applies in `hilbert_POD_func`, and it feeds CCA's 50% mode-count threshold.
- **Patch:** use `eValue/trace(R)` (svds branch: ‖U‖²_F).
- **Check:** patched twin jet gives 4.41 / 3.02 / 2.46 / 1.49 %, equal to the true shares.

**Acoustic wavenumber lines in both wavenumber scripts: drawn too far out.**
- The code uses k_aD = 2π·M_j·St. The correct value is k_aD = 2π·St·(u_j/c∞)·(D/D_j), with St = f·D_j/u_j.
- At NPR 2.9 the old line sat at ±3.59 rather than ±2.95, about 20% too far out.
- With the patch, the upstream (−k) band in the twin-jet spectrum lies on the line.

**`get_wavenumber` (mean-field shock wavenumbers): truncated and slightly mis-scaled.**
- It used `data(idx_y, idx_x0:nx)`, which drops the last `idx_x0−1` columns.
- The sample spacing was `span/nx` instead of `span/(nx−1)`.
- Patched.

## 3. Other bugs found and patched

**Reconstruction (`SPOD_Mode_Frequency_Reconstruction`)**
- The bandwidth index `find((St − bw/2) == min(abs(St − bw/2)))` is missing an `abs` on the left. It errors whenever the nearest bin lies below bw/2, so it works or fails depending on nfft and fps.
  - The patch uses a half-width of `round(bw/2/dSt)` bins. That is 1 bin narrower each side than the old version when it worked. `bandwidth_range` now saves the bandwidth actually kept.
- Mach branches:
  - they saved into `<main>/Data` (the raw-data folder), so HPOD never found them;
  - filenames came out as `"_Modes_1_1  2_"`;
  - one `save_file` line is commented out by a pasted `\n`.
- `n_modes_set = 0` broke `invspod`.
- The bandpass branch used an undefined `bandwidth_range`.
- `specific_freqs_inds` saved the max-energy bin, not the requested one.
- The SPOD file was reloaded for each St.
- The save code was duplicated 6 times. The patch replaces it with one save; NPR filenames are unchanged.

**Time–frequency (`SPOD_Time_Frequency_Analysis`)**
- No `_Mj_` branch (crash).
- `input()` prompt, which stalls batch jobs (now a warning).
- `steps = n_snapshots/1000` is non-integer for most frame counts.

**Symmetric SPOD (`SPOD_Analysis_Symmetry_Enforced`)**
- `nfft` is computed from an undefined `n_snapshots`; `nfft` and `overlap` are now parameters at the top.
- `get_symmetry` returned double (2× memory; out of memory on the second pass). It now keeps single precision.
- The Mach branch saved under `parent_folder`, which nothing reads.
- Saves were not `-nocompression`.
- Axis handling checked: the twin case snaps to row 95, so the output has 189 rows, matching `y`.

**BMD (`BMD_Analysis`, `bmd_modified`, `BMD_Plots`)**
- Absolute `MinPeakProminence = 1e6`. The twin jet got 0 peaks and the Mach case 1. The patch requires peaks to stand 1 decade above their surroundings in L, which gives 2 and 9 peaks.
- `break` skipped every remaining case; now `continue`.
- `triadics` was not cleared between cases.
- `bmd_modified` stored `Q_hat` as complex double over all nDFT frequencies, about 28 GB for either case. It now keeps only the frequency rows used by the triads.
- `opts.precision = true` never selects single, because the option is compared with the string `'single'`.
- BMD_Plots:
  - crashed with fewer than 10 triads;
  - its non-Specfreqs branch ran `findpeaks` on values already sorted by size, so it found nothing;
  - the interaction map `real(P1.*P2)` carries twice the arbitrary eigenvector phase, so its sign is meaningless. The patch uses `conj(P1).*P2`.

**Plot scripts**
- POD_Plots:
  - `pod_type` selects the subfolder (`''`, `'CCA'`, `'Symmetry_Imposed'`); `ROI = false` by default;
  - the phase-portrait axis labels were swapped.
- Hilbert_POD_Plots: NPR/M is now parsed from the current file; `ROI = false` by default.

**Wavenumber scripts**
- `SPOD_2D_Wavenumber_Spectrum_Analysis`:
  - no `_Mj_` parse; `NPR(i)` in the Mach branch; `case_list{ii}`;
  - the magenta line repeats `k_kh_s1`;
  - the Log/Abs figure names are swapped;
  - fewer than 4 peaks crashes.
- `_Simple`: reads `SPOD_Results`, handles `_Mj_`, and the dead symmetric suffix is fixed.

**Empirical_Dispersion**
- The file pattern is now a `case_suffix` parameter (was hard-coded `*Imposed*Fields.mat`).
- St = f·D_j/u_j like the other scripts. Check: after the patch, the tones sit at St 0.43 / 0.86 (twin jet) and 0.54 / 0.81 / 1.08 (Mach case).
- c∞ comes from T0 = 293 K, matching `get_ideal_jet_velocity_diameter`, instead of 340.
- Mach detection now has an else branch.
- The 3-row average is clipped at the frame edges.
- Not changed:
  - with `overlap = 0` and `nfft = 4096`, a 10k-frame record gives 2 blocks and drops 1,808 frames, so set `overlap = 50`;
  - the title always says D_e.

**Separate_Upstream_Downstream**
- `D_eff` falls back to `D`.
- Both branches now save the split field as `im_data`. Before, the NPR branch saved `im_data_series` and the Mach branch saved the unsplit data.
- The `Data` folder is created.
- The integer NPR/M code is saved, matching the other `*_Fields.mat` files.

- **`CCA_POD_Analysis` / `CCA_POD_func`:**

- **`spod.m`:**
  - with `restrict_memory = true`, the temporary-file names don't match;

  - `set_frequencies` is ignored unless `restrict_memory` is set.

- **The wavenumber `y_D` choice for twin jets:**
  - the default and `set_own_y_D = 0.5` both fall in the gap between the jets;
  - the mean-field k_s is taken at y = 0, which is also between the jets.
  - Worth choosing y = ±s/2 explicitly.
- **Wavenumber log plot:** `clim([-5 1])` is applied to `log(abs(·))` of an un-normalised spectrum, so the limits depend on the data's scale.
- **Toolboxes:** almost every script uses `extractfield`, which needs the **Mapping Toolbox**.

## 5. Usage pitfalls and suggestions

- **Wildcards:** `parent_folder_str` and `main_folder_str` need a `*`. With an exact name, `dir` lists the folder's *contents*, and the scripts loop over `.`, `..` and the subfolders.
- **Silent no-ops:** several plot scripts do nothing and give no message when no files match (POD_Plots, Hilbert_POD_Plots with `ROI = true`). A `warning` when `case_list` is empty would help everywhere.
- **Absolute thresholds:** BMD's `MinPeakProminence`, the wavenumber `mode_peak_index < 50` and `clim` all depend on the intensity scale, pixel count, fps or nfft. Express them relative to the data (decades of L, St, or normalised values).
- **Memory, for local runs or smaller HPC jobs:** the patched HPOD, `tcoeffs`, `get_symmetry` and `bmd_modified` keep peak memory near one or two copies of the data. The originals needed 3–6.
- **The time–frequency result is worth a look:**
  - the twin-jet tone steps from St 0.431 to 0.425 at t ≈ 0.044 s;
  - SPOD convolution coefficients and HPOD on the reconstruction agree on it;
  - HPOD also shows short phase-slip spikes when the amplitude dips.

## 6. Workflow improvements for a shared toolbox

These scripts are used by many students on different rigs, so the goal is generality without making them hard to read. The tests in this review point to a few root causes. Most of the bugs above are copies of the same logic that drifted apart.

**Duplicated logic that drifted:**
- NPR/Mach handling exists in about 15 copies, with `_Mj_`, `_M_` and `_Ma_` variants, so several scripts crash on Mach cases.
- St has two definitions and the acoustic line two formulas.
- Peak picking has four different rules (absolute thresholds, bin-index cut-offs).
- Each save block is duplicated for NPR and Mach. Six copies in one script had already drifted.
- The `_Symmetry_Enforced` scripts are forked copies of their parents and lag behind them.

**Other root causes:**
- **Hard-wired paths and settings at the top of every script.** The last user's paths stay in: `CCA` in POD_Plots, `ROI = true`, `Market = true` in BMD.
- **Silent failures.** An empty `dir` result either does nothing or crashes on `case_list{1}`.
- **No tests.** The amplitude and conjugation errors went unnoticed because nothing compares outputs with a known answer.

The recommendations below keep the current style: parameter-at-top scripts that a student can read top to bottom. The repeated machinery moves into a few small, well-named functions. There are no classes, frameworks or packages to learn.

### 6.1 Quick wins (each is small and independent)

1. **One `find_cases` helper.** It replaces the `get_parent_path` + `dir` + `extractfield` block in every script:
   ```matlab
   cases = find_cases(Top_folders, parent_folder_str, main_folder_str, "SPOD_Results/Data", "*Nfft*.mat");
   ```
   It returns a struct array (`file`, `main_folder`, `save_folder`, `condition`). It should:
   - add the `*` if the user forgot it (§5);
   - skip `.` and `..`;
   - `warning` and return empty when nothing matches;
   - print the number of cases found.

   This removes the commonest silent failure, and the Mapping Toolbox dependency (`extractfield`) along with it.
2. **One `flow_conditions` function.**
   ```matlab
   fc = flow_conditions(filename_or_meta)
   ```
   It returns `NPR`, `M_j`, `u_j`, `D_j`, `a_j`, `c_inf`, `T0`, plus `St_from_f = @(f) f*D_j/u_j` and `k_acoustic = @(St) ...`. Every script then computes St, acoustic lines and labels the same way. This review found two St definitions and two acoustic-line formulas. Making `T0` and the nozzle design Mach number inputs (defaults 293 K, M_d = 1) also fixes D_j for C-D nozzles.
3. **One `find_peaks_St` function.**
   ```matlab
   [idx, St_pk] = find_peaks_St(L, St, 'n', 4, 'decades', 1, 'St_min', 0.05)
   ```
   Use it in SPOD_Plots, BMD, wavenumber, time–frequency and reconstruction. Thresholds are relative (decades of L) and limits are in St, not bins. A requested `n` larger than the number of peaks found is handled; that crashed BMD_Plots and the wavenumber script.
4. **Save the parameters with every output.** Put `params` (every top-of-script setting), `source_files` and the git commit hash (`git rev-parse HEAD` through `system`) into each result file. Plot scripts and later readers then never re-parse filenames for `nfft` or overlap, and every result can be traced to the code that made it.
5. **Batch safety.**
   - Never `input()`, `ginput` or `pause` unless an `interactive` flag is set.
   - `close all` after each figure.
   - Save figures with `exportgraphics`, which is much faster than `export_fig -m5`. Per-frame `export_fig` made the sample videos and the separation script take about 1 hour each on the 10k-frame cases.
   - For videos, write frames with `VideoWriter` (MPEG-4) and skip PNG + ffmpeg. That also removes the ffmpeg install and module dependency.
6. **Fail loudly with a message that names the problem.** When a crash would be confusing, check first and stop with a clear message. For example: `"No SPOD file with nfft = 4096 for <case>: run SPOD_Analysis first"`, or `"case_suffix matched 0 files in <folder>"`.

### 6.2 Medium changes (worth doing together, one script family at a time)

7. **Metadata in the data file, not the filename.**
   - `Schlieren_Load_to_mat` should write a `meta` struct: `NPR` or `M_j`, `D`, `T0`, nozzle name, view (`Major`/`Minor`/`Angled`), twin spacing `s/D`, `fps`, camera, knife-edge orientation, background used, rotation angle.
   - Every later script copies `meta` forward and reads from it.
   - Filename parsing (`get_filename_params`) stays only as a fallback for old files. A one-off `Update_old_datafiles` pass can add `meta` to existing files.

   This removes the token inconsistency (`_Mj_` vs `_M_`), the NPR ≥ 10 limit, the digit-count decoding, and the guessing of axis labels and `nozzle_centre` from words in the filename. It also lets a student process a new geometry without editing string-matching code.
8. **Thin driver scripts plus analysis functions.** Each script keeps its parameter block, but the body becomes one call:
   ```matlab
   %% SPOD_Analysis.m  (driver: edit the parameters, then run)
   cfg = schlieren_paths();            % per-user paths: see item 9
   p.nfft = 4096;  p.overlap = 50;  p.modes_to_keep = 4;  p.symmetry = "none";  % "none" | "2-region"
   cases = find_cases(cfg.data_root, "*Schlier*", "*ONR*", "Data", "*Fields.mat");
   for c = cases
       run_spod(c, p);                 % Functions/run_spod.m: load, SPOD, save (with params + meta)
   end
   ```
   - Students still see and edit everything that matters.
   - The function has its own workspace, so there are no stale variables between cases and no `clear all`. In the old structure, stale `triadics`, `X_proj` and `L_peaks_inds` all caused crashes or wrong results.
   - The function can be tested on synthetic data.
   - MATLAB `arguments` blocks give defaults and type checks, with no extra syntax for students to learn.
9. **Per-user paths in one gitignored file.**
   - Add `schlieren_paths.m`, which returns `cfg.data_root`, `cfg.save_root`, `cfg.temp_root` and `cfg.on_hpc`. It is created from a committed `schlieren_paths_example.m`.
   - Scripts no longer carry the last user's MASSIVE or Market paths, and nobody commits theirs.
   - `using_MASSIVE = 1-ispc` and the Market gvfs logic live in one place.
10. **Fold the `_Symmetry_Enforced` variants into their parents.**
    - A `p.symmetry` option calls `get_symmetry` before the decomposition and `undo_symmetry` after it.
    - The same applies to Mach/NPR branches: one code path, with `meta` deciding the labels.
    - This removes about 2,000 duplicated lines, which is where most of the drift happened.
11. **Separate analysis from plotting everywhere.** Analysis scripts save data; plot scripts take a list of result files.
    - This is already mostly true. Exceptions: Time-Frequency plots inside its analysis loop; Empirical_Dispersion saves no data, only figures; Separate_Upstream_Downstream only makes videos unless a flag is set.
    - A small `label_axes(meta)` helper and a `plot_style()` keep figures consistent: x/D vs x/D_e, y vs z*, fonts, colormaps.
12. **A memory estimate before the heavy step.**
    - Print the expected peak memory before running, and warn if it exceeds the available memory (`memory` on Windows, `/proc/meminfo` on Linux). For example, SPOD needs about 2 × data, and the patched HPOD about 3 × data.
    - Students then find out before the job is killed, not after an hour of loading.
    - The patches in this folder already keep peak memory to 1–3 copies of the data.

### 6.3 Making correctness checkable

13. **A `tests/` folder that runs in a few minutes on a laptop.**
    - Synthetic generators: a travelling wave with known f, k and amplitude; a mirror-symmetric field with a known tilt; a two-tone signal with a frequency jump.
    - Tests for each core function:
      - Parseval for `spod`;
      - amplitude round-trip for `invspod`;
      - phase direction and amplitude for `tcoeffs` and HPOD;
      - axis and angle for `align_fields`;
      - k-sign convention for `get_wavenumber` and `separate_flow_direction_function`;
      - triad detection for `bmd`.
    - `tests/test_spod_hpod_scaling.m` and `tests/test_align_fields.m` here are the start of this. MATLAB's `runtests` can collect them.
14. **A small reference dataset with expected outputs.**
    - Keep one cut-down case, for example the twin jet here cropped to about 2k frames, plus a short `expected.mat`: tone St, HPOD f_inst, POD energy, axis row.
    - A `smoke_test.m` runs the whole pipeline on it and compares.
    - Run it before merging changes to `main`. It would have caught every crash in §1.
15. **Conventions written down once.**
    - Add a one-page `CONVENTIONS.md` covering:
      - array order: `im_data` [y, x, t]; SPOD `P` [f, y, x, mode];
      - units: x, y in D; D in mm;
      - St = f·D_j/u_j;
      - the Fourier sign: e^{+iωt}, so +k is downstream;
      - which mean is subtracted where;
      - output folder layout.
    - Several header comments are currently wrong (P dims, "mm"). Short headers pointing to this page are easier to keep correct than long ones.

### 6.4 Repository hygiene

- Keep `main` runnable. Students branch for their own changes and merge back after `smoke_test` passes.
- The README still uses old script names. Replace it with the pipeline diagram and a "which script do I run for…" table.
- Move `Functions/Misc` scripts that are one-off analyses, or that call old function signatures, into an `Archive/` folder, or delete them.
- Add `*.asv` to `.gitignore`. There are `.asv` files in `Functions/` and `Functions/Misc/`.
- Replace helpers with built-ins where possible: `sgolayfilt`/`sgolay` for `savgol_diff` (its end padding biases end derivatives), `exportgraphics` for `export_fig`, `VideoWriter` for ffmpeg. Fewer external pieces means fewer setup problems for new students.

### 6.5 Suggested order

1. Merge the patches in this folder.
2. Do 6.1 (items 1–6). These are mostly mechanical and each stands alone.
3. Write `CONVENTIONS.md` and the smoke test (items 13–15), so the refactor in step 4 can be checked.
4. Do 6.2 script family by script family, starting with the main path: Load → SPOD → Reconstruction → HPOD → Plots. Convert one family at a time and check it against the smoke test before moving on.

### 7.2 Bugs worth knowing about (found this round)

- **`Read_slow` read every frame 810 bytes late.**
  - `textscan` reads the header and leaves the file position inside the JSON. The header skip then started from there instead of from the start of the file.
  - Each image moved up by about one row and wrapped 170 columns sideways, with a visible seam. The next frame's metadata bytes landed in the last row.
  - Reading all frames ran off the end of the file.
  - Fixed with `frewind`. You saw no seams in older files, so earlier MATLAB versions may have left the file position elsewhere. Check any `.slow`-derived Fields file for a vertical seam before trusting it.
- **`tcoeffs` phase reference.**
  - Each coefficient's phase was referenced to the start of its window, not to the time step it is assigned to. That multiplies bin b by (−1)^(b−1).
  - It doesn't matter for |a| or for a single bin. Any sum over neighbouring bins (a band field) cancelled instead of adding.
  - The coefficient is now referenced to the window centre. This was found while building §7.4: the band-field instantaneous frequency had an rms error of 41 Hz before the fix and 0.56 Hz after.
- **`correct_phase_between_halves`** (twin-jet halves).
  - It shifted half 2's coefficient phase by +θ. That was right only for the conjugated modes the old `hilbert_POD_func` returned. With the corrected HPOD it must be −θ, otherwise ψ is offset by 2θ.
  - Its direction checks compared `phase(100)` values, which depend on the arbitrary phase offset, so modes could be conjugated at random.
  - Fixed. `tests/test_half_slices_phase.m` recovers a known ψ to 0.001 rad.
- **`align_fields` with `auto_position = "none"` (the default)** discarded `y_0` and put y = 0 at the frame centre. It now keeps `y_0` (your choice), crops symmetrically about it, and stops with a message if `y_0` is outside the frame. Rotation also crops the zero-filled corners now.
- **`get_filename_params`:**
  - It used the last file's digit count for every case, so `_Mj_080` and `_Mj_0834` in one folder decoded wrongly.
  - It cut nozzle names at `_Major`/`_Minor`.
- **CCA:**
  - The dense n_pix × n_pix covariances (about 18 GB per half here) are replaced by the exact same CCA computed in the space of the kept POD modes. It matches the original to 1e−13 (`tests/test_cca_pod.m`) and works on full fields.
  - Also fixed: an undefined `mode_inst_phase`, the ROI = 1 size mismatch, the conjugated Hilbert transform and two different regularisations.
- **`spod_adapt`** modes had norm 1/sqrt(nSamples), so P·A ≠ Q̂. They now have unit norm and Parseval holds.
- **`bmd_modified_Symmetry`:** L was initialised with zeros before `spmdReduce(@addnan)`, so with more than one worker most triads came back 0.
- **`simple_POD_func` / `hilbert_POD_func`:**
  - The svds branch scaled modes and coefficients differently from the other branches.
  - ROI bounds that fell exactly between two grid points gave two indices.
- **Wildcards:**
  - `match_folders` replaces `dir(fullfile(parent, pattern))` everywhere. An exact folder name now matches that folder; before, it listed the folder's contents, and the scripts looped over `.`, `..`, `Data` and so on.
  - An empty match warns.
- **Smaller fixes:**
  - `savgol_diff` padded the ends with constant values, which biased end derivatives towards 0.
  - `separate_flow_direction_function` didn't remove the mean in its time-series branch.
  - `get_background`: missing backgrounds errored; a TIFF inside a condition folder was ignored; `im2double(...,'indexed')` added 1 to every pixel.
  - Flat-field correction did integer division.
  - `Read_mraw` read 16-bit data as signed.
  - SPOD_Plots waterfall and OAE didn't work for more than one case.
  - The wavenumber script overwrote its data file for every peak, and `y_width`/`band_range` had no effect.
  - `undo_symmetry*` and `get_symmetry` allocated in double, doubling memory.
  - `D_j` is now right for C-D nozzles (optional `M_d` input).

### 7.3 Finding x = 0 without a background (aerospike)

The original axial method finds the first rise of the mean along the centreline. With no background, and with a body on the axis, it finds the downstream end of that body. For the aerospike that is the spike tip, about 1.25 D downstream of the nozzle exit.

**New method: `Functions/find_nozzle_exit.m`** (`axial_method = "lip"` in `Schlieren_Load_to_mat`). It uses two fields that need no background:
- **The nozzle body is dark and quiet.** Pixels are body if they are dark in the mean and have a low temporal std (no flow, only camera noise). The thresholds come from a 3-level Otsu split of each field, so they don't depend on bit depth or exposure. Only regions touching the upstream edge are kept.
- **The lips are where the shear layers start.** For each row, the body ends at some column. The lips are the outermost rows on each side of the axis where the high-std jet starts at the body edge. A second estimate, the outermost std peak 5–20 px downstream, catches shear layers that start slightly downstream of the lip. The more outward of the two is kept.
- **The exit plane** is the body edge at the lip rows, refined to sub-pixel accuracy with the steepest mean-field rise.

Results:
- **Aerospike:** exit at column 107.5, lips 79 px apart (1.25 D_eq), spike tip at column 187. x = 0 is at the lip, as intended.
- **Impingement:** exit at column 40.4. The lips are 113 px apart against 114.8 px from your D and scale (0.98 D printed).
- **Robustness:** the result is stable to cropping the frame by 2–4 columns.

The loader prints the lip-to-lip distance in D, which also checks D and `mm_per_pixel`.

Other options, if a geometry defeats this:
1. A reference image of the nozzle (or a target at the exit plane), taken with the run, defining x_0 once per setup.
2. Template matching of the known nozzle outline against the mean field.
3. Use the spike tip, which the centreline method finds reliably, as the reference, and subtract the known spike length.

Option 1 is the most robust for students and is worth adding to the lab procedure.

### 7.4 HPOD on an SPOD-isolated band (`tcoeffs` route)

`Hilbert_POD_Analysis` now has `data_source`:
- **`"raw"`:** HPOD of the data.
- **`"reconstructed"`:** the `invspod` route through `Data_Reconstructed`.
- **`"spod_tcoeffs"`:** new. For each SPOD bin in `St_specified ± bandwidth_St/2`, set as in `SPOD_Mode_Frequency_Reconstruction`, and for `n_modes_set` modes, `tcoeffs` gives a sliding-window coefficient at every time step. The band field Σ P·a is analytic, so no Hilbert transform is needed.

Its POD is computed exactly without forming the field (`hpod_from_spod_tcoeffs`: a K × K Gram matrix, with K = bins × modes). There are no block joins, so there is none of the instantaneous-frequency floor `invspod` leaves (HPOD_Switch_Benchmark).

Results:
- **Synthetic test** (FM tone plus an interfering tone plus noise): rms error against the true f(t) is 0.56 Hz with `tcoeffs`, against 2.80 Hz for HPOD of the raw data (`tests/test_hpod_tcoeffs.m`).
- **400k-frame case on M3:** all 400k frames (31 bins × 2 modes around St 0.695) took about 6 minutes. HPOD of the raw data can't be run at that length: its snapshot matrix would be 400k × 400k.

### 7.5 Memory on long records (and the old `restrict_memory` route)

**Measured on M3** (400k frames, 200 × 512 px; the data are 82 GB as int16, 164 GB as single):

| Step | Peak RSS | Time |
|---|---|---|
| SPOD (nfft 4096, 50 %) | 501 GB | 14.5 min |
| SPOD_Time_Frequency (St 0.05–1.1) | 338 GB | 27.5 min |
| HPOD, `spod_tcoeffs` | 354 GB | 6 min |
| BMD (spec-freqs) | 331 GB | 6 min |
| HPOD, raw data | 121 GB | 37 min |
| POD (snapshot) | 92 GB | 13 min |
| SPOD_Plots | 2.5 GB | 0.7 min |

All eight steps finished without errors (job 61383781, m3h110, 1 h 45 min in total). The outputs take about 21 GB next to the data.

- **SPOD at 501 GB** is the single-precision data (164 GB) plus the block FFTs (Q̂: nFreq × pixels × blocks ≈ 2 × the data in complex single, 328 GB).
- **The other ~330 GB peaks** are two single copies of the data, from loading, converting to single and then permuting to time-first.

**What the old `restrict_memory` (`opts.savefft`) does.** Measured locally on 3,000 frames of the twin jet, nfft 256:
- It writes one file per block with all frequencies: Q̂ on disk, the same ~2 × data as in memory. For 400k frames that would be about 330 GB.
- It also writes one `spod_f####.mat` per frequency (2,049 files at nfft 4096), and these are never deleted.
- For every frequency it loads every block file in full to extract one row, so the total read is nFreq × the block files. On the small test it took **1,285 s against 12 s in memory**. At 400k frames that read pattern would take days.

**New, less extreme route** (no files, identical results):
- **Frequency batches in `spod.m`:** `opts.freq_batches`, or `opts.max_memory_GB` as a budget, set through `max_memory_GB` in `SPOD_Analysis`. The block FFTs are recomputed for each batch of frequencies, and only that batch's rows of Q̂ are kept. The cost is one extra pass of FFTs per batch.
- **Data kept in its stored class (int16)** and read straight into time-first order (`load_fields_time_major`). `spod` and `tcoeffs` convert each block or row to single as they use it. This also applies to SPOD_Time_Frequency and the `tcoeffs` HPOD route.

Local profile on 3,000 frames (data 1.13 GB as single):

| Variant | Peak memory | Time | Temp files |
|---|---|---|---|
| Old, in memory | 5.00 GB | 12 s | — |
| Old, `savefft` | 2.92 GB | 1,285 s | 2.0 GB of blocks, plus 129 `spod_f` files left behind |
| New, 1 batch | 4.84 GB | 20 s | — |
| New, 4 batches | 3.01 GB | 13 s | — |
| New, 8 batches | **2.53 GB** | 22 s | — |

L and P are identical to the old in-memory result in every case (`tests/test_spod_freq_batches.m`).

**Measured on M3, 2026-10-24** (400k case, same inputs as `SPOD_Analysis`; each variant in its own MATLAB; jobs 61428940, 61429453 and 61429454; scripts in `Large_Test/Code/Batch_Test`):

| Variant | Predicted peak | Measured peak | `spod` time | vs the final SPOD file |
|---|---|---|---|---|
| Old code (single data, 1 batch) | — | 501 GB | 14.5 min | (is the reference) |
| New, 1 batch (int16 data) | 417 GB | **416 GB** | 12.8 min | L 3.0e-7; mode 1 at the tone 1.000000 |
| New, 4 batches | 172 GB | **177 GB** | 20.1 min | L 3.0e-7; mode 1 at the tone 1.000000 |
| New, 8 batches | 132 GB | **138 GB** | 21.9 min | L 3.0e-7; modes 1–2 at 17 frequencies (tone, ends, both sides of every 4- and 8-batch boundary) all 1.000000 |
| New, `"auto"` on a 300 GB job | 251 GB (chose 2 batches) | **256 GB** | 19.5 min | L 3.7e-7; mode 1 at the tone 1.000000 |

- **The memory estimate holds.** The peak is data + one batch of FFT blocks + modes, plus about 5 GB for MATLAB itself.
- **Batches cost little time.** The 8-batch run took 1.7× as long as one batch, not 8×. Loading the data (2–4 min, not included in the times above) and the eigen-decompositions don't repeat; only the block FFTs do.
- **Results are the same in every variant.** The L differences of 3e-7 are single-precision rounding against the reference, which was computed from single-precision data with a single-precision mean. The 2-batch run, on a different node, differs from the others in the seventh digit.
- **The `"auto"` budget works under SLURM.** It read the 300 GB allocation (322 GB decimal), set a 274 GB budget, picked 2 batches and peaked at 256 GB.
  - Its first attempt was killed at 314 GB. That exposed a bug: each new batch's FFT array was allocated while the previous one was still held, briefly needing 2 batches' worth. `spod` now clears the old array first.
  - The 1-batch result above was unaffected, since one batch never reallocates.
- **For a 1.4 TB MASSIVE desktop:** `max_memory_GB = "auto"` (now the `SPOD_Analysis` default) uses one batch up to records of about 1.1 TB of data + FFT blocks. It batches automatically beyond that.

`restrict_memory` is kept for compatibility but no longer recommended. Time–frequency and `tcoeffs` HPOD should drop from ~340 GB to about 100 GB with the new loader; this has not been measured on M3 yet.

### 7.6 The twin-jet half workflow: making it part of the toolbox

**Current workflow:**
1. `Functions/Misc/Generate_Twin_Half_Slices_POD_HPOD_Fields.m` writes two new Fields files per case (`_Half_1`, `_Half_2`), doubling the storage.
2. The normal scripts run on them.
3. `Half_Slices_Hilbert_POD_Analysis` (or CCA) compares the halves.

**Fixed this round:**
- The generator kept only one frame for records shorter than 1.2 s, because of a hard-coded `t_target`.
- The halves could differ in size.
- The `straight_to_*` branches used old function signatures.
- The comparison script had the ψ sign problem (§7.2) and a hard-coded path.
- The comparison script now saves ψ, β, Δf, the phase-locking R and θ, as well as the figures.

**Suggested formalisation:**
1. **No duplicate Fields files.** Give POD/HPOD (and SPOD) a `split_halves = true` option that runs the decomposition on rows above and below the axis (half 2 flipped), using the same axis row and y as `get_symmetry`. This is the same indexing the symmetry scripts already use, so no new geometry code is needed. The outputs are the `_Half_1`/`_Half_2` result files the comparison already reads.
2. **One comparison script in the main folder** (`Twin_Jet_Half_Comparison.m`), replacing `Half_Slices_*`. It should:
   - read HPOD, `spod_tcoeffs` HPOD or CCA results for both halves;
   - align them with `correct_phase_between_halves`;
   - save ψ(t), β(t), Δf(t), R and θ;
   - plot them with the shared style.
3. **Use the `spod_tcoeffs` HPOD route for the halves when one tone dominates.** Both halves are then projected onto the same SPOD band, so their instantaneous frequencies are directly comparable and much less noisy than raw HPOD.
4. **Symmetric/antisymmetric SPOD already measures the same thing in a block-averaged way:** the energy split between symmetric and antisymmetric parts at the tone. Report it next to ψ statistics, so the time-resolved and averaged views of coupling sit side by side.
